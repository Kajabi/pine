# Box

Box is our primitive layout component. It is intended to be used as a building block for more complex layouts. It allows for custom sizing, colors, padding, and alignment while still adhering to Pine tokens and brand guidelines. The component uses logical properties for margin and padding, making it adaptable to different writing modes and languages.

## Quick Start

### Essential Concepts
- **Default behavior**: Items flow horizontally (row direction)
- **For vertical stacking**: Use `direction="column"`
- **Inside pds-row**: Box is a column of the row's 12-column grid (size it with `size` props)
- **Standalone**: Box is a flexbox container (use alignment props)
- **Host classes and styles**: The component keeps the classes and inline styles it puts on its host. If something removes them, such as a DOM morph, it puts them back, so change its layout through props. Classes and styles you add yourself are left alone. A script that undoes them as soon as they come back (from a `MutationObserver`, say) wins after a few rounds, and the component logs a console warning.

### Most Common Props
- `direction`: `"row"` (default, horizontal) or `"column"` (vertical stacking)
- `gap`: Spacing between items - accepts t-shirt sizes (`"none"`, `"xxs"`, `"xs"`, `"sm"`, `"md"`, `"lg"`, `"xl"`, `"xxl"`) or core spacing tokens (`"025"`, `"050"`, `"100"`, `"125"`, `"150"`, `"200"`, `"250"`, `"300"`, `"350"`, `"400"`, `"450"`, `"500"`, `"550"`, `"600"`, `"650"`, `"700"`, `"750"`, `"800"`)
- `padding`: Internal spacing (same size options as gap)
- `justify-content`: Horizontal alignment (`"start"`, `"center"`, `"end"`, `"space-between"`, etc.)
- `align-items`: Vertical alignment (`"start"`, `"center"`, `"end"`, `"baseline"`, `"stretch"`)

### Logical Properties
The Box component uses CSS logical properties for layout and spacing, which means properties are defined relative to the content's writing direction rather than physical directions. This makes the component more adaptable to different writing modes and languages.

**Key concepts:**
- **Block**: Perpendicular to text flow (usually vertical)
- **Inline**: Parallel to text flow (usually horizontal)
- **Block-start/end**: Top/bottom in most languages
- **Inline-start/end**: Left/right in LTR languages, right/left in RTL

This approach ensures layouts work correctly regardless of text direction or writing mode.

## Guidelines

### When to use

- Stacking content vertically (`direction="column"`) or lining items up side by side, spaced with `gap`: cards, toolbars, button groups and form sections.
- Surfaces such as cards and panels that need padding, a border, rounded corners, a shadow or a background.
- Columns inside a `pds-row`. Place the box directly inside the row and size it with `size` props.
- Aligning items, or pushing one to the far side of a row with an `auto` margin.

### When not to use

- Capping content at a readable width. Use `pds-container`.
- A rule between unrelated blocks of content. Use `pds-divider`; the border props are for edges that belong to the box.
- Spacing below a heading or paragraph. Use the `pds-text` `gutter` prop.
- Spacing siblings apart with `margin-*` props. Use `gap` on the parent box.
- Styling a `pds-row` column. Put border, padding, background and shadow on a `pds-box` inside the column, so they don't replace or enclose the row's gutter.

### Accessibility

- `pds-box` adds no role or semantics. Use headings, lists and landmark elements, such as `nav` or a `pds-container` with `tag`, to structure the content.
- Reading and focus order follow the DOM order. No `pds-box` prop reorders its children, so write the markup in the order the content should be read.

### When a box needs `fit`

A box is `inline-flex` unless you change `display`, so on its own it's only as wide as its content. `fit` sets its `width`, `min-width` and `max-width` to `100%`, so it fills its parent instead.

- **A box that isn't inside another box** shrinks to its content. Add `fit` (or `display="flex"`) when it should fill its container, such as a page section, a card body or a footer whose `justify-content` should spread its children.
- **A box in a `direction="column"` parent** stretches to the parent's width, as long as the parent doesn't set `align-items`. Once the parent sets `align-items` to anything other than `stretch`, each child shrinks to its content. Add `fit` to a child that should still span the column.
- **A column parent sizes to its widest child.** A child with `fit` can only fill what its parent has, so a column that should span the page needs `fit` on the column too.
- **Don't combine `fit` with `size` or `auto`.** Use `size` inside `pds-row` and `fit` everywhere else.

### Pushing a box to the far side

Set `margin-inline-start="auto"` on a box to push it, and everything after it, to the end of a row, such as Cancel and Save on one side of a footer and Delete on the other. `margin-inline-end="auto"` pushes what follows it away. In a column, `margin-block-start="auto"` pushes a box to the bottom of a column that has a height. The row needs to be wider than its content for the margin to do anything, so give it `fit` too. Every pds-box in the row needs `flex="none"` or `flex="shrink"`, or the `auto` prop, the pushed box and its siblings alike: a box with the default `flex-grow` takes the free space itself, which leaves the margin nothing to take. Buttons, text and other non-box children don't grow, so they're fine as they are.

Use `justify-content="space-between"` when every child should spread out evenly, and an `auto` margin when only one should move.

### Truncating text in a box

Text that doesn't wrap, such as `pds-text truncate`, still counts toward the width of every box around it, so it can widen its column rather than truncate. Set `container="inline-size"` on the column that should hold the text to its width.

### Growing and shrinking

- `flex="none"` keeps a box at its content size: it won't grow, and it won't shrink when the row runs out of space.
- `flex="shrink"` sizes a box to its content and lets it give way when space runs out, without growing.
- `flex="grow"` makes a box take the space that's left.

## Layout Fundamentals

### Direction: The Most Important Decision

> **Direction Rules:** Choose based on how you want **direct children** to arrange:

#### Use `direction="column"` (Vertical Stacking) When:
- **Stacking content vertically** (headings, paragraphs, buttons)
- **Creating page sections** (hero, content, footer)
- **Making card layouts** (image, title, description, actions)
- **Creating main containers** (usually with `fit="true"`)

#### Use `direction="row"` (Horizontal Flow) - DEFAULT When:
- **Placing items side by side** (buttons, badges, icons)
- **Creating navigation bars** (logo, menu items, user profile)
- **Building toolbars** (action buttons in a row)
- **Making inline layouts** (icon + text, multiple form fields)

### Working with PDS-Row

> **KEY LAYOUT RULE:** When `pds-box` is a direct child of `pds-row`, it's a **column** of the row's 12-column grid. Everywhere else, it's a **flexbox container** for its own children.

**Inside pds-row (as a column):**
- Use `size` props (1-12) to control column widths
- The default `direction="row"` works well for grid layouts
- **DON'T size columns with `flex`.** `pds-row` is a wrapping flex row and each column starts at `width: 100%`, so `flex="grow"`, `flex="none"` or `flex="shrink"` gives an unsized column a full line. See [Row: Columns](/docs/components-layout-row--docs#columns) for the column rules.

**Standalone (Flexbox Container Mode):**
- Default `direction="row"` creates horizontal flow
- Set `direction="column"` for vertical stacking
- **DO use flex props** - they work for child boxes

### Common Layout Patterns

- **Horizontal Flow (Default)**: Items side by side - good for buttons, navigation
- **Vertical Stacking**: `direction="column"` for content that should stack - pages, cards, forms
- **Main Containers**: `direction="column"` and `fit="true"` for page sections
- **Grid Layout**: Use inside `pds-row` with `size-*` props for responsive grid

### Display
By default Box is `display: inline-flex`. Use `display` to change the display property `flex` if the box is intended to fill the entire row.

Layout impact:
- `flex`: Creates a flex container (default)
- `inline-flex`: Creates an inline flex container
- `block`: Creates a block-level container
- `inline-block`: Creates an inline-block container

### Wrap
Controls whether flex items wrap to new lines when they don't fit in the container.

**Options:**
- `false` (default): Items stay on one line and may overflow (equivalent to `flex-wrap: nowrap`)
- `true`: Items wrap to new lines as needed (equivalent to `flex-wrap: wrap`)
- **Responsive variants**: `wrap-xs`, `wrap-sm`, `wrap-md`, `wrap-lg`, `wrap-xl`

### Margin
Controls external spacing around the container using logical properties. By default Box has no margin. There's no `margin` shorthand prop, so set each side you need (accepts both t-shirt sizes and core spacing tokens, or `auto`):
- `margin-block-start` / `margin-block-end` (top/bottom)
- `margin-inline-start` / `margin-inline-end` (left/right in LTR)
- `auto` takes up the free space on that side, to push the box to the far side of its parent. See [Margin auto](#margin-auto).
- **All support responsive variants**

> Note: Use `gap` in favor of `margin-*` whenever possible.

### Margin auto
Every `margin-*` prop and its breakpoint variants also take `auto`. An `auto` margin takes up the free space on its side, so `margin-inline-start="auto"` pushes a box, and everything after it, to the end of its row. The row needs room to spare, so give it `fit`. Every pds-box in the row needs `flex="none"` or `flex="shrink"`, or the `auto` prop, the pushed box and its siblings alike: a box with the default `flex-grow` takes the free space itself, which leaves the margin nothing to take.

<DocCanvas

### Justify Content

## Sizing Properties

### Size

Grid system:
- Uses a 12-column grid system
- Values range from 1-12 (e.g., `6` = 50% width, `12` = 100% width)
- Most effective when used inside `pds-row` containers
- Responsive variants available: `size-xs`, `size-sm`, `size-md`, `size-lg`, `size-xl`

### Offset
`offset` moves a column toward the end of its `pds-row` by a number of columns, from `0` to `12`, by adding that fraction of the row's width as a start margin. Breakpoint versions such as `offset-md` work like the size props. Use it on a column that has a `size`.

<DocCanvas
  mdxSource={{
    react: `<PdsRow colGap="sm">
  <PdsBox sizeMd="4" offsetMd="4">
    <PdsBox border padding="sm">size-md 4, offset-md 4</PdsBox>
  </PdsBox>
</PdsRow>`,
    webComponent: `<pds-row col-gap="sm">
  <pds-box size-md="4" offset-md="4">
    <pds-box border padding="sm">size-md 4, offset-md 4</pds-box>
  </pds-box>
</pds-row>`
  }}>
  <pds-row col-gap="sm">
    <pds-box size-md="4" offset-md="4">
      <pds-box border padding="sm">size-md 4, offset-md 4</pds-box>
    </pds-box>
  </pds-row>
</DocCanvas>

### Auto
`auto` sizes a box to its content and stops it from growing or shrinking. In a `pds-row`, it makes a column as wide as its content, and the columns without a size share what's left. Only the base `auto` does this in a row: on a column without a `size`, `auto-sm` to `auto-xl` give it a full line instead.

<DocCanvas

  </PdsBox>
</PdsRow>`,
    webComponent: `<pds-row col-gap="sm">

  </pds-box>
  <pds-box>
    <pds-box border padding="sm">This column takes the rest of the row</pds-box>
  </pds-box>
</pds-row>`

    <pds-box auto>
      <pds-box border padding="sm">auto</pds-box>

### Min Width and Min Height
`min-width` and `min-height` set the box's minimum size, as any CSS length such as `300px` or `10rem`. A `min-height` gives the box room to align its items vertically, as in the [Align Items](#align-items) examples.

<DocCanvas
  mdxSource={{

  }}>

    At least 300px wide and 120px tall, with its content centered
  </pds-box>

### Flex
The `flex` prop controls how a box grows or shrinks within its container. It accepts both predefined values and custom CSS flex values.

> **Inside `pds-row`, size columns with `size`, not `flex`.** A column starts at `width: 100%`, so the predefined values give a column without a `size` a full line. A custom value with a basis, such as `flex="1"`, does share the row. Outside a row, `flex` works on a box whose parent is a flex container, such as another `pds-box`.

#### Predefined Values
- `none` - The box will not grow or shrink (equivalent to `flex: 0 0 auto`)
- `grow` - The box will grow to fill available space (equivalent to `flex: 1 1 auto`)
- `shrink` - The box sizes to its content and shrinks when space is limited, but won't grow (equivalent to `flex: 0 1 auto`)

<DocCanvas
  mdxSource={{
    react: `<PdsBox>
  <PdsBox border="true" flex="none">Flex: none</PdsBox>
  <PdsBox border="true" flex="grow">Flex: grow</PdsBox>
  <PdsBox border="true" flex="shrink">Flex: shrink</PdsBox>
</PdsBox>`,
    webComponent: `<pds-box>
  <pds-box border="true" flex="none">Flex: none</pds-box>
  <pds-box border="true" flex="grow">Flex: grow</pds-box>
  <pds-box border="true" flex="shrink">Flex: shrink</pds-box>
</pds-box>`
}}>
  <pds-box>
    <pds-box border="true" flex="none">Flex: none</pds-box>
    <pds-box border="true" flex="grow">Flex: grow</pds-box>
    <pds-box border="true" flex="shrink">Flex: shrink</pds-box>

`none` and `shrink` both size a box to its content. The difference shows when the row runs out of room: a `shrink` box gives way and wraps its text, and a `none` box keeps its width and overflows.

- `"2"`: Grows twice as much as `flex="1"` items

### Fit
`fit` sets the box's `width`, `min-width` and `max-width` to `100%`, so it fills its parent's width. A box is `inline-flex` by default and sizes to its content, so use `fit` for a box that should span its container. See [When a box needs `fit`](#when-a-box-needs-fit).

In a `direction="column"` parent that sets `align-items`, a child without `fit` shrinks to its content, so `justify-content` has no room to work. With `fit`, it spans the column:

    <pds-text>End</pds-text>

### Container
`container` sets the box's `container-type`, which makes it a size container:

- `inline-size`: the box's width no longer comes from its content. Text that doesn't wrap, such as `pds-text truncate`, truncates at the box's width instead of widening it and every box around it. Children can also use container query units (`cqi`) and `@container` queries against the box's width.
- `size`: the same for both width and height. The box's content no longer sets its height either, so give it one some other way (`min-height`, or a stretched flex item), or it collapses.

A box with `container` still needs its width from somewhere else, such as `flex="grow"` or the default `flex-grow` in a row. In a row, `flex="none"` or `flex="shrink"`, or the `auto` prop, leaves it with no content width to size to, and it collapses -- drop them and keep the default or `flex="grow"` instead; adding `fit` there would take the whole row and push its siblings out. A standalone box, or a child of a column that sets `align-items`, collapses for the same reason but has no siblings to push out, so add `fit` to it there.

<DocCanvas
  mdxSource={{
    react: `<PdsContainer size="sm">
  <PdsBox fit border padding="sm" gap="sm" alignItems="center">
    <PdsBox container="inline-size" direction="column">
      <PdsText truncate>A long file name that should truncate rather than push the action out of the card.pdf</PdsText>
    </PdsBox>
    <PdsButton variant="secondary">Replace</PdsButton>
  </PdsBox>
</PdsContainer>`,
    webComponent: `<pds-container size="sm">
  <pds-box fit border="true" padding="sm" gap="sm" align-items="center">
    <pds-box container="inline-size" direction="column">
      <pds-text truncate>A long file name that should truncate rather than push the action out of the card.pdf</pds-text>
    </pds-box>
    <pds-button variant="secondary">Replace</pds-button>
  </pds-box>
</pds-container>`
}}>
  <pds-container size="sm">
    <pds-box fit border="true" padding="sm" gap="sm" align-items="center">
      <pds-box container="inline-size" direction="column">
        <pds-text truncate>A long file name that should truncate rather than push the action out of the card.pdf</pds-text>
      </pds-box>
      <pds-button variant="secondary">Replace</pds-button>
    </pds-box>
  </pds-container>
</DocCanvas>

In current browsers, `container` doesn't apply layout or paint containment (some of the first browser versions with container queries applied layout containment too), so it doesn't clip the box's content or trap a positioned dropdown or tooltip inside it. It does apply style containment, so CSS counters and quotes restart inside the box.

## Direction Troubleshooting

### Problem: Items Not Arranging as Expected

#### Issue: Content stacking when you want side-by-side
```tsx
// ❌ Problem: Buttons stack vertically instead of horizontally
<PdsBox direction="column">
  <PdsButton>Save</PdsButton>
  <PdsButton>Cancel</PdsButton>
</PdsBox>
```

**Solution:** Remove `direction="column"` or use `direction="row"` (default):
```tsx
// ✅ Solution: Buttons appear side by side
<PdsBox>
  <PdsButton>Save</PdsButton>
  <PdsButton>Cancel</PdsButton>
</PdsBox>
```

#### Issue: Content appearing side-by-side when you want stacking
```tsx
// ❌ Problem: Title and text appear next to each other
<PdsBox>
  <h1>Page Title</h1>
  <p>Description text</p>
</PdsBox>
```

**Solution:** Add `direction="column"`:
```tsx
// ✅ Solution: Title appears above description
<PdsBox direction="column">
  <h1>Page Title</h1>
  <p>Description text</p>
</PdsBox>
```

### Quick Decision Tree for LLMs:

> **Direction decision rules:**
> 1. **Are you building a page/card/form?** → Use `direction="column"`
> 2. **Are you placing buttons/badges/icons together?** → Use default (no direction needed)
> 3. **Are children meant to stack vertically?** → Use `direction="column"`
> 4. **Are children meant to flow horizontally?** → Use default (no direction needed)

## Responsive Sizing Strategies & Examples

The `pds-box` component uses a mobile-first approach to responsive sizing. This means that styles cascade up from smaller breakpoints to larger ones, unless overridden at a specific breakpoint.

### Understanding the Cascade

- The base `size` prop sets the default width that applies to all breakpoints unless overridden
- Breakpoint-specific props (`size-xs`, `size-sm`, etc.) override the base size at their respective breakpoints and larger
- Each breakpoint-specific prop overrides any sizes set by smaller breakpoint props

### Breakpoint Behavior

See the [Responsive Breakpoints](#responsive-breakpoints) table for the breakpoint ranges.

### Common Patterns

#### Stacking on small screens, columns on larger screens

```html
<!-- Full width on mobile, half width on tablets and up -->
<pds-box size="12" size-md="6"></pds-box>

<!-- Full width on mobile, one-third width on tablets and up -->
<pds-box size="12" size-md="4"></pds-box>
```

#### Explicit full-width layout on small screens

```html
<!-- Explicit full width on mobile, different widths at different breakpoints -->
<pds-box size="12" size-sm="6" size-lg="4"></pds-box>
```

#### When to use/avoid the base `size` prop

The base breakpoint is what a phone renders. A base `size` below `12` is
therefore a narrow column **on the smallest screen**, not just on large ones —
`size="6"` is half the viewport on a phone, and nothing overrides it.

Avoid the base prop for content that should stack on small screens — use the
full-width-then-widen pattern above (`size="12" size-md="6"`) instead.

Use the base prop when the element genuinely should stay narrow at every width —
a checkbox or icon gutter beside a body column, for example, where a full-width
phone layout would be wrong:

```html
<!-- Deliberately narrow at every breakpoint, including mobile -->
<pds-box size="2"></pds-box>
```

If you need different sizes at different breakpoints:

```html
<!-- Different widths at different breakpoints -->
<pds-box size-sm="12" size-md="6" size-lg="4"></pds-box>
```

### Default Behavior

When no size props are provided, the box will use `flex-grow: 1` and `flex-basis: 0`, allowing it to grow and fill available space while maintaining equal widths with other flex items.

```html
<!-- These boxes will share available space equally -->
<pds-row>
  <pds-box></pds-box>
  <pds-box></pds-box>
</pds-row>
```
