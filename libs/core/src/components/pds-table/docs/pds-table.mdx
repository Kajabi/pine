# Table

Tables display tabular data using semantic subcomponents for head, head-cell, body, row, and cell roles. Use pds-table-head, pds-table-head-cell, pds-table-body, pds-table-row, and pds-table-cell to compose rows and columns accessibly.

## Guidelines

### When to use

- For displaying important data to users in an organized format.
- When the organized data needs to be sorted.

### When not to use

- For building layouts. Please use [Box](/docs/components-layout-box--docs) and [Row](/docs/components-layout-row--docs) instead.

### Accessibility

Be sure to make proper use of the subcomponents to ensure that the table is accessible to screen reader users.

The sort icon is hidden from assistive technology. To announce the sort direction, set `aria-sort` on the sorted `pds-table-head-cell`, `ascending` when the event's direction is `asc` and `descending` when it's `desc`, updating it from the `pdsTableSort` event and removing it from the other head cells.

Sortable head cells can't take focus and don't respond to keys, so the built-in sorting works only with a pointer.

When a row's checkbox changes, that `pds-table-row` emits `pdsTableRowSelected` with `{ rowIndex, isSelected }`. `rowIndex` is the row's position in the body, which changes when the table is sorted, so to match a selection to your data, give each row a `data-id` and read `event.target.dataset.id` in the handler. The select-all checkbox emits `pdsTableSelectAll` from `pds-table-head` with `{ isSelected }`. Select all sets every row's `isSelected` without emitting `pdsTableRowSelected`, so listen for both. A row or head that starts with `is-selected` also emits its event on load. Setting `is-selected` in code after that emits nothing, and the select-all checkbox doesn't update to match.

```javascript
const table = document.querySelector('pds-table[component-id="members"]');

table.addEventListener('pdsTableRowSelected', (event) => {
  const memberId = event.target.dataset.id;
  // Add memberId to your selection when event.detail.isSelected is true, or remove it.
});

table.addEventListener('pdsTableSelectAll', (event) => {
  // event.detail.isSelected now applies to every row.
});
```

In React, pass `onPdsTableRowSelected` to each `PdsTableRow`, so the handler already knows its item, and `onPdsTableSelectAll` to `PdsTableHead`.


### Sorting

Add `sortable` to a `pds-table-head-cell` to let readers sort the table by that column. Clicking the head cell sorts the rows by the text in that column and shows an arrow for the direction.

- The first click on a column sorts it in descending order, and each click after that reverses it. Each column keeps its own direction, so going back to a column reverses the direction it had.
- Sorting by a column clears the arrow from the column sorted before it.
- Rows are compared as text, ignoring case, so numbers sort by their digits: `10` comes before `9`.
- The built-in sort finds a column by counting only the sortable head cells. When a column that isn't sortable comes before a sortable one, sorting reads the wrong column's cells, so mark every column `sortable`, or [sort the rows yourself](#sorting-rows-yourself).
- The built-in sort and the default sort only find head cells that have the `sortable` attribute. When `sortable` is set only as a property, as React 19 does on a raw `pds-table-head-cell` tag, clicking shows the arrow but doesn't sort.

#### Sort event

Each click emits `pdsTableSort` from the clicked `pds-table-head-cell`. The event bubbles to `pds-table`, which sorts the rows when the event reaches it. `detail.column` is the head cell's text, trimmed, and `detail.direction` is the new direction, `asc` or `desc`. Set `aria-sort` to match, as described in [Accessibility](#accessibility).

#### Sorting rows yourself

Sort the rows yourself when they come from a server, or when React or another framework renders them. The built-in sort empties `pds-table-body` and puts back only the rows, so it moves elements the framework rendered and drops anything else in the body, such as the comment markers some frameworks leave there.

To stop the built-in sort, call `preventDefault()` on `pdsTableSort`, then render the rows in the order `detail.direction` gives. The table sorts as soon as the event reaches `pds-table`, so the call has to come first: listen on `pds-table-head` or the head cells, or listen in the capture phase. A listener on `pds-table` or `document` runs after the rows have moved. Canceling doesn't stop the head cell from showing the new direction.

```javascript
document.querySelector('pds-table-head').addEventListener('pdsTableSort', (event) => {
  event.preventDefault();
  const { column, direction } = event.detail;
  // Sort or fetch your rows by column and direction, then render them.
});
```

In React, pass the handler to each sortable `PdsTableHeadCell` and render the rows from state:

```jsx
import { useState } from 'react';
import {
  PdsTable, PdsTableBody, PdsTableCell, PdsTableHead, PdsTableHeadCell, PdsTableRow,
} from '@pine-ds/react';

const fields = { Name: 'name', Email: 'email' };

export function MembersTable({ members }) {
  const [sort, setSort] = useState(null);

  const handleSort = (event) => {
    event.preventDefault();
    setSort(event.detail);
  };

  const rows = sort
    ? [...members].sort((a, b) => {
        const field = fields[sort.column];
        const order = a[field].localeCompare(b[field]);
        return sort.direction === 'asc' ? order : -order;
      })
    : members;

  const ariaSort = (column) => {
    if (sort?.column !== column) return undefined;
    return sort.direction === 'asc' ? 'ascending' : 'descending';
  };

  return (
    <PdsTable componentId="members">
      <PdsTableHead>
        {Object.keys(fields).map((column) => (
          <PdsTableHeadCell key={column} sortable onPdsTableSort={handleSort} aria-sort={ariaSort(column)}>
            {column}
          </PdsTableHeadCell>
        ))}
      </PdsTableHead>
      <PdsTableBody>
        {rows.map((member) => (
          <PdsTableRow key={member.id}>
            <PdsTableCell>{member.name}</PdsTableCell>
            <PdsTableCell>{member.email}</PdsTableCell>
          </PdsTableRow>
        ))}
      </PdsTableBody>
    </PdsTable>
  );
}
```

### Default Sort

The `defaultSortColumn` value must match the text content of a sortable column header exactly. The default sort doesn't emit `pdsTableSort`, so set the matching initial `aria-sort` on that head cell yourself. The first click on that column reverses the default direction.

### Responsive

When the `responsive` prop is set to `true`, the table scrolls horizontally when it's wider than its container.

- Shadows at the inline-start and inline-end edges show when there's more to scroll. With `fixed-column`, the start shadow stays hidden.
- The table doesn't reflow: there's no stacked or card layout on small screens. For wide tables, add `fixed-column` so the first column stays in view. With `selectable`, that column slides over the checkboxes as the table scrolls (see [Fixed Column](#fixed-column)).
- The table is a Tab stop, but arrow keys don't scroll it. Keyboard users can only bring hidden columns into view by tabbing to controls inside them.

### Cell Truncation

When the `truncate` prop is set on a `pds-table-cell`, the cell keeps its text on one line and cuts off what doesn't fit the column with an ellipsis. While the text is cut off, the cell is a Tab stop and shows a tooltip with the full text on hover and focus.

Truncation doesn't set the column's width. In the default layout, a truncated cell counts as at most 100px wide when the table divides its width among the columns (`--pds-table-cell-truncate-max-width` changes this), and the column still ends up wider when the table has room. To give a column an exact width, use `table-layout="fixed"` with a `width` on its head cell, as in [Column Widths](#column-widths).

### Column Widths

By default, a table sizes each column from the content on the page, so a column can change width when the rows change, for example after a sort. To keep columns put, set `table-layout="fixed"` on `pds-table` and a `width` on the `pds-table-head-cell` of each column whose size you know. Columns without a `width` share the space that's left, so leave one column (usually the one with the longest content, such as a name) without a width and add `truncate` to its cells.

- `width` accepts any CSS length (e.g. `148px`, `12rem`, `20%`) and includes the cell's padding.
- In a fixed layout, content never resizes a column. Content longer than its column overflows, so add `truncate` to cells whose content may not fit.
- In a `responsive` table, the table scrolls horizontally when the column widths add up to more than the container.
- Without `table-layout="fixed"`, `width` sets the column's minimum width, and the column can still grow to fit its content.

#### Column widths with horizontal scrolling

Add `responsive` to a fixed-layout table when its columns can add up to more than the space it has. The table keeps every column at its `width` and scrolls horizontally instead of squeezing them.

- A column without a `width` keeps at least 120px. When the set widths leave it less than that, the table grows wider and scrolls rather than shrinking it further.
- Add `truncate` to cells whose content may be longer than their column, such as names and tag lists.
- For tables wide enough that the first column scrolls out of view, add `fixed-column` so it stays in place (see [Fixed Column](#fixed-column)).
