# Row

Row is a flexbox-based grid container that arranges content into responsive columns. It uses a 12-column system for laying out horizontal rows.

## Guidelines

### When to use

- Responsive layouts with two or more columns on a 12-column grid, such as a main column beside a sidebar or a grid of cards.
- Columns that stack on small screens and sit side by side from a breakpoint up.

### When not to use

- A single line or stack of items, such as a toolbar, a button group or a form. Use a `pds-box` with `gap`.
- Capping content at a readable width. Use `pds-container`.
- Tabular data. Use `pds-table`.
- Styling a column directly. Put `border`, `padding`, `background-color` and `shadow` on a `pds-box` inside the column, so they don't replace or enclose the gutter.

### Accessibility

- `pds-row` and its columns add no role or semantics. Use headings, lists and landmark elements inside the columns to structure the content.
- Columns keep their DOM order when they wrap, and that order is the reading and focus order. Write the markup in the order the content should be read.

## Columns

Row is a wrapping flex row that always lays its columns out horizontally. Its direct children are its columns, so make each one a `pds-box`.

- Size columns with `size` props (`1` to `12`). Columns with no size share the width the sized columns leave, equally.
- Nothing limits the total. Columns whose sizes add up to more than 12 wrap to a new line.
- A column without a `size` shares the row only while it has no layout or border props of its own. With `direction`, `display`, `gap`, `wrap`, `fit`, `container`, `offset`, a `flex` preset or a border prop (or a breakpoint version of one of these, or of `auto`), it takes a full line. Give it a `size`, or move those props to a `pds-box` inside it.
- Use `size` props, not `flex`, to size columns. A column starts at `width: 100%`, so `flex="grow"`, `flex="none"` or `flex="shrink"` on an unsized column gives it a full line. A custom value with a basis, such as `flex="1"`, does share the row.
- Put the column's border, padding, background and shadow on a `pds-box` inside it, as the examples below do. `col-gap` is padding on the column, so padding on the column replaces the gutter, and a border or background on it wraps around the gutter too.

### Common Patterns

- `size="6"` + `size="6"` = 50/50 split
- `size="4"` + `size="8"` = 33/67 split
- `size="3"` + `size="3"` + `size="6"` = 25/25/50 split

### Responsive Patterns

- `size-md="6"` + `size-md="6"` = 50/50 on medium+ screens
- `size-sm="12"` + `size-md="6"` = Full width on small, half on medium+

## Responsive Breakpoints

The breakpoint props on `pds-box` columns use these ranges: `xs` below 576px, `sm` 576px and up, `md` 768px and up, `lg` 992px and up, and `xl` 1200px and up. See the [Box breakpoint table](/docs/components-layout-box--docs#responsive-breakpoints) and the [Layout documentation](/docs/components-layout--docs#responsive-breakpoints) for more detail.

### Wrapping
If the size values add up to more than 12, the boxes wrap to the next line. `size` applies at every screen width. `size-xs` applies only below 576px, so use `size` or a larger breakpoint prop when the layout must wrap on wider screens too.

### Align Items

Defines the vertical alignment of the row items.

Layout impact:
- `start`: Items align to the top of the row
- `center`: Items align to the center of the row
- `end`: Items align to the bottom of the row
- `baseline`: Items align to their text baseline
- `stretch`: Items stretch to fill the row height (default)

Best practice: Use with `min-height` for consistent vertical alignment

### Column Gap

The `pds-row` component provides flexible gap control with three different props for precise spacing management.

#### Gap Props Overview

- **`col-gap`**: Sets both horizontal and vertical spacing between items
- **`col-gap-inline`**: Sets only horizontal spacing between items (overrides `col-gap` for horizontal)
- **`col-gap-block`**: Sets only vertical spacing between items (overrides `col-gap` for vertical)

#### How the gutter works

Without `col-gap`, `col-gap-inline` or `col-gap-block`, columns have no gutter. The gap props add padding on every side of each column, and give the row a negative margin of the same size on every side:

- The space between two columns' content is twice the value. `col-gap="sm"` (16px) leaves 32px between columns, and 32px between wrapped lines.
- The negative margin lines the column content up with the edges of the row's parent, so the row's own box reaches one gap past its parent on every side. When the parent has no padding and meets the edge of the viewport, that overhang can make the page scroll horizontally.

#### Gap sizes

Each gap prop takes a t-shirt size or a core spacing token. The `lg`, `xl` and `xxl` gutters are wider than the same names on `pds-box` `gap` and `padding`, which are 32px, 40px and 48px.

**Layout impact:**
- Controls the gap between columns in the grid
- Creates consistent spacing between all columns
- Works with both fixed-size and auto-width columns

**Best practice:** Use `md` or `lg` for comfortable spacing between content columns

#### When to Use Each Gap Prop

- **`col-gap`**: Use when you want uniform spacing in both directions (most common)
- **`col-gap-inline`**: Use when you need different horizontal spacing than vertical (e.g., wide columns, tight rows)
- **`col-gap-block`**: Use when you need different vertical spacing than horizontal (e.g., tight columns, spaced rows)

**Common Patterns:**
- **Cards Layout**: `col-gap="lg"` for even spacing
- **Form Layout**: `col-gap-inline="md" col-gap-block="sm"` for tighter vertical spacing
- **Navigation**: `col-gap-inline="lg"` with no vertical gap
- **Dense Grid**: `col-gap="xs"` for minimal spacing

### Justify Content

Layout impact:
- `start`: Columns pack toward the left (default)
- `center`: Columns pack toward the center
- `end`: Columns pack toward the right
- `space-between`: Columns are evenly distributed with first at start, last at end
- `space-around`: Columns are evenly distributed with equal space around them

Best practice: Use `space-between` for navigation or action buttons

### Min Height

Layout impact:
- Sets a minimum row height, so the row can be taller than its content
- `align-items` positions columns within that height
- Prevents row height from collapsing when content is short

Best practice: Use `min-height` only when the row must be taller than its content. `align-items="center"` already centers columns against the tallest column without it.

Example: `min-height="100px"` or `min-height="10rem"`

### No Wrap

Layout impact:
- Prevents columns from wrapping to new lines
- Columns may overflow horizontally if total width exceeds container
- Useful for navigation bars or horizontal scrolling layouts

Note: Can cause horizontal overflow if columns are too wide

Best practice: Use sparingly, only when you need to prevent wrapping

### Layout Properties
`pds-row` creates the horizontal rows that are used to contain a set of columns and can be viewed on the [Layouts](/docs/components-layout--docs) page.

## Technical notes

The component keeps the classes and inline styles it puts on its host. If something removes them, such as a DOM morph, it puts them back, so change its layout through props. Classes and styles you add yourself are left alone. A script that undoes them as soon as they come back (from a `MutationObserver`, say) wins after a few rounds, and the component logs a console warning.
