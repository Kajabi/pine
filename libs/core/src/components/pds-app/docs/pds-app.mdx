# App frame

> **Proposal, not yet design-reviewed.** Filed as <a href="https://linear.app/kajabi/issue/DSS-237">DSS-237</a>. This is a scaffold matching that ticket's acceptance criteria, built to make the shape concrete for review — treat every visual and API decision here as a starting point, not a settled answer.

`pds-app` is a slot-driven application shell: a fixed header, an optional side nav, and a scrollable main stage — replacing the pattern of wrapping Pine content in Sage's `SageBody`/`SageHeader`/`SageStage`.

## Guidelines

### When to use

- The top-level frame of an admin-style application — one `pds-app` per page, wrapping everything else.
- Anywhere currently composing `SageBody` + `SageHeader` + `SageStage`, or hand-rolling the same three-region layout from `pds-box`.

### Why one component, not three

Body/Header/Stage in Sage are empty structural wrappers — their only value is a documented, consistent frame. Bundling them as slots on one component means there's one shape to learn instead of three components nobody composes the same way twice.

## Slots

- `header` — fixed top bar, not scrolled with the page. Typically a `pds-topbar`. Collapses to nothing when empty.
- `nav` — optional side navigation. Collapses to nothing when empty, so a page with no nav doesn't reserve space for it.
- default — the scrollable main stage. Rendered inside a `pds-container` using the same `size` scale (`mainSize` prop), so this is also how a page gets its content max-width.
