# Icon
Icons render scalable glyphs from Pine's icon set, representing actions, statuses, or features in the interface.

## Guidelines

### When to use

- Use icons to visually represent actions, features, or common concepts to enhance the user experience.
- Ideal for buttons, navigation elements, status indicators, or any context where small visual cues can add clarity.

### When not to use

- Avoid using icons as the sole means of communication without accompanying text or labels, as this may confuse users.
- Do not use icons for complex ideas that require explanation or context that cannot be clearly conveyed through visuals alone.

### Accessibility

- Ensure sufficient contrast between the icon and the background for visibility.
- Don't rely solely on icons for critical actions.
- A decorative icon needs no attributes. `pds-icon` is hidden from assistive technology unless you name it, so it adds nothing to the accessible name of the control it sits in: `<button>Remove <pds-icon name="remove"></pds-icon></button>` is read as "Remove". An icon's `name` is an asset id rather than copy, so it is never used as a label.
- Give an icon an `aria-label` only when it carries meaning on its own, such as a status icon with no text beside it. A named icon is exposed as an image with that name.
- The control still needs its own name, because the icon no longer supplies one. Name an icon-only control with `aria-label` on `pds-button`, or leave the text in the default slot, which `icon-only` hides visually but not from screen readers.

## Finding icons

To browse the icon set, open the `name` control in the [Playground](#playground) at the end of this page. It lists every icon in the `@pine-ds/icons` version this Storybook uses.

Each icon has one name, written two ways:

- Web components use the kebab-case name: `<pds-icon name="info-circle"></pds-icon>`.
- React imports the camelCase form of the same name from `@pine-ds/icons/icons`: `import { infoCircle } from '@pine-ds/icons/icons'`. Numbers stay in place, so `circle-1` becomes `circle1`.

A name that doesn't exist renders nothing. The only signs are a failed request for the SVG and a console warning. AI tools can check a name with the `list_pine_icons` tool in [Pine MCP](/docs/resources-pine-mcp--docs).

- **Do:** `<pds-icon name="info-circle"></pds-icon>`. **Don't:** `<pds-icon name="infoCircle"></pds-icon>`, or a guessed name such as `name="info"`.
- **Do:** `<PdsIcon icon={infoCircle} />`. **Don't:** `<PdsIcon name="info-circle" />`, which renders but logs a warning and fetches the SVG at runtime instead of bundling it.

## Examples

### Color

Icons inherit the surrounding text color (`currentColor`) by default, so most icons need no `color` at all. To set one, prefer a semantic token, which is designed for both light and dark mode:

- Semantic tokens: `var(--pine-color-icon)`, `var(--pine-color-icon-subtle)`, or a status color such as `var(--pine-color-success)`. A raw token such as `--pine-color-icon-subtle` works too.
- Any other CSS color, such as `#FF0000`, `rgb(255, 0, 0)` or `hsl(0, 100%, 50%)`. Use these only as an escape hatch: they stay the same in light and dark mode.

### Custom SVG

To show an icon that isn't in Pine's set, such as a partner logo, set `src` to the URL of an SVG file: `<pds-icon src="/images/partner-logo.svg"></pds-icon>`. The icon fetches the file, so it must be served from the same origin or with CORS headers.

Use `src` only for SVG files you trust. The icon inserts the file's markup as it is, without sanitizing it.

### Right-to-left

Directional icons, such as `arrow-left`, `arrow-right` and `caret-left`, mirror automatically when the page's `dir` is `rtl`, or when the icon has its own `dir="rtl"`. Other icons don't mirror on their own. `flip-rtl` changes that:

- Add `flip-rtl` to mirror an icon that isn't directional in right-to-left text, or a directional icon inside a `dir="rtl"` section of a left-to-right page, which doesn't mirror automatically.
- Set `flip-rtl="false"` to keep a directional icon from mirroring, such as in a `dir="ltr"` section of a right-to-left page.

Automatic mirroring is decided when the icon renders, so a directional icon already on the page doesn't mirror if the page's `dir` changes to `rtl` afterward.

Here, `flip-rtl` mirrors the arrow inside a right-to-left section:

## Usage

### React Usage

In React, import the icon from `@pine-ds/icons/icons` and pass it to the `icon` property, which bundles the SVG with your app. `name` isn't deprecated, but in React it logs a console warning and fetches the SVG at runtime from the [asset path](/docs/guides-assets--docs) (jsDelivr by default).

```jsx
import { bulb, danger, launch } from '@pine-ds/icons/icons';
import { PdsIcon } from '@pine-ds/react';

// Correct usage
<PdsIcon icon={bulb} />
<PdsIcon icon={danger} color="var(--pine-color-danger)" />
<PdsIcon icon={launch} size="large" />
```

### Web Component Usage

For web components, use the `name` property with the icon name as a string:

```html
<pds-icon name="bulb"></pds-icon>
<pds-icon name="danger" color="var(--pine-color-danger)"></pds-icon>
<pds-icon name="launch" size="large"></pds-icon>
```

## Performance

### Individual Icon Imports

When you know exactly which icons you need, import them individually for optimal bundle size:

```jsx
import { danger, bulb } from '@pine-ds/icons/icons';

<PdsIcon icon={danger} />
<PdsIcon icon={bulb} />
```

### Multiple Icon Imports

For components that use several icons, import multiple icons in a single statement:

```jsx
import {
  danger,
  bulb,
  launch,
  downSmall
} from '@pine-ds/icons/icons';
```

### Bundle Size

- **Individual imports**: Recommended for better tree-shaking and smaller bundle sizes
- **Avoid wildcard imports**: Don't use `import * from '@pine-ds/icons/icons'` as this imports all icons
- **Bundle size**: Each icon adds approximately 1-2KB to your bundle
- Avoid importing icons in shared utility files unless necessary
- Consider lazy loading for icons used in less common user flows

## Troubleshooting

### Console Warning About Name Property

If you see this warning in your console:

> "In Pine React, you import icons from "@pine-ds/icons/icons" and set the icon you imported to the "icon" property. Setting the "name" property has no effect."

The icon still renders, but it's fetched at runtime from the asset path instead of being bundled.

**Solution**: Replace the `name` property with proper icon imports:

```jsx
// ❌ Incorrect - causes warning
<PdsIcon name="danger" />

// ✅ Correct - no warning
import { danger } from '@pine-ds/icons/icons';
<PdsIcon icon={danger} />
```

### Icon Not Showing Up

1. **Check your import**: Ensure the icon is imported from `@pine-ds/icons/icons`
2. **Verify icon name**: Check that the icon name matches exactly (see [Finding icons](#finding-icons))
3. **React vs Web Component**: Use `icon` property for React, `name` for web components
4. **Check the asset path**: An icon set with `name` loads from the [asset path](/docs/guides-assets--docs) at runtime, so make sure the SVG assets are served there

## Technical Notes

- React uses the `icon` property while web components use `name`. This difference is intentional and optimized for each framework's strengths.
- In React, icons are imported as objects from `@pine-ds/icons/icons` and passed to the `icon` property. This provides type safety, editor autocomplete, and tree-shaking—only imported icons are bundled.
- In web components, the `name` property accepts string values for simpler HTML-like syntax, following standard web component attribute patterns.
- Setting the `name` property in React triggers a console warning directing developers to use the `icon` property instead. The icon still renders, but it's fetched at runtime from the asset path instead of being bundled.
