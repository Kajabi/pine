# Input

Input captures a single line of text from the user, paired with a label and optional helper or error message. Use it for names, emails, IDs, and other short freeform values.

## Guidelines

### When to use

- To gather basic usage information.
- For responses that are a single line of text.

### When not to use

- For responses longer than one line. Consider using a [Textarea](/docs/components-textarea--docs).
- For responses from a predefined list. Consider using a [Select](/docs/components-select--docs).

### Accessibility

For accessibility, it is strongly encouraged to follow these best practices:

- Use the `label` property to help screen reader users identify the purpose of the input.
- Always set `label`, even when the design shows no label: `hide-label` hides it visually and keeps it as the input's name, and also hides the `action` slot. Without `label`, the input renders no `<label>` and no `action` slot.
- Do not use a `placeholder` to communicate the field label, use a `label` property.
- Provide clear and descriptive error, helper, and placeholder messages.
- The helper message, or the error message while `invalid` is set, becomes the input's accessible description.

The text moves over to make room for `prefix` and `suffix` content, so keep it short. `Tab` moves through focusable slot content in the order it shows: `prepend`, `prefix`, the field, `suffix`, then `append`.

### Working with Labels

When analyzing designs or screenshots, text that appears above an input field is the input's label, not a separate `pds-text` component. The `label` prop creates text that appears above the input field and integrates properly with the component's styling and accessibility features.

### Character Limits

`maxlength` caps how many characters people can type, except with `type="number"`, where browsers ignore it; bound a number with `min` and `max` instead. It's all lowercase, as on a native `<input>`; `pds-textarea` spells the same limit `max-length` and adds a character counter.

## Form Integration

- Provide a `name` so the value is submitted with the form. An empty field is left out of `FormData`, where a native input would submit an empty string.
- Use the `value` prop with `onPdsInput` when you need a controlled field; omit `value` for uncontrolled forms.
- A value that fails `required`, `pattern`, `min`, `max`, `step`, `minlength` or its `type`'s check stops the form from submitting, as on a native input. `maxlength` stops people typing past the limit instead. The input doesn't set `invalid` itself, so set `invalid` and `error-message` when you show an error.
- Resetting the form clears the value to an empty string, not back to the `value` it started with.
- For a complete form, with validation and debugging, see [Using Pine form components](/docs/guides-forms--docs).
