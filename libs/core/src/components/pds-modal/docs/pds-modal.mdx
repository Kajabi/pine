# Modal

By default, modals show content in a dialog that blocks interaction with the page until it closes. Use them for confirmations, focused forms, or details that need attention without leaving the page.

## Guidelines

### When to use

- Use modals to display content that temporarily blocks interactions with the main view
- For complex forms that need focused attention
- To confirm important actions
- To show detailed information without leaving the current context

### When not to use

- For non-critical information that doesn't require immediate attention
- For complex workflows that require multiple steps; use a full page instead
- When the content can be displayed directly on the page

### Accessibility

- Name the dialog: it's labelled by the element with the id `{component-id}-heading`, so give the modal's heading that id.
- Include a close button in the header, with an `aria-label` such as "Close modal".
- When the modal opens, focus moves to its first control. When it closes, focus returns to the control that opened it.
- `backdrop-dismiss="false"` turns off Escape as well as backdrop clicks, so keep a clear way out, such as a Cancel or Close button.
- `disable-top-layer` doesn't trap focus or make the page inert. Use it only when an overlay has to show above the modal (see [Overlays Above the Modal](#overlays-above-the-modal)).

### Subcomponents

The Modal component is composed of several subcomponents that work together to create a complete modal experience:

#### Modal Content

The `pds-modal-content` component provides a container for the main content of the modal. By default, modals are scrollable when content exceeds the available space. You can control this behavior using the `scrollable` prop on the main modal component. The content component automatically handles border visibility based on scroll state. It adds no padding, so wrap its content in a `pds-box` with `padding-inline-start="md"` and `padding-inline-end="md"`, as the examples do.

The `pds-modal-header` component holds the modal's title and close button. It adds no padding or layout, so wrap its content in a `pds-box` with `padding="md"`.

### Opening and Closing

#### Using Buttons

Set `open` to `true` to open a modal and to `false` to close it, or call `showModal()` and `hideModal()`. The [Default](#default) example wires its buttons this way: `onclick` attributes in HTML, state in React.

#### Using Events

The modal closes itself on Escape, a backdrop click and the browser's own close request, and sets its own `open` to `false` when it does. `pdsModalClose` fires whenever the modal closes, whether it closed itself, you set `open` to `false`, or you called `hideModal()`. It can fire twice for one close, so keep its handler safe to run again. `pdsModalOpen` fires about 100 ms after the modal opens, once it has set its initial focus. It fires even if the modal closed in the meantime, after `pdsModalClose`, so check `open` in its handler when that matters.

If you keep `open` in state, update that state in `pdsModalClose` (`onPdsModalClose` in React). Otherwise your state stays `true` after the modal closes itself, so setting it to `true` again doesn't reopen the modal, and your component's next re-render does. The event bubbles, so a modal nested inside another modal's markup also reaches the outer modal's listener; check `event.target` there.

```javascript
const modal = document.querySelector('#my-modal');

modal.addEventListener('pdsModalOpen', () => {
  console.log('Modal opened');
});

modal.addEventListener('pdsModalClose', () => {
  console.log('Modal closed');
});
```

#### Dismiss Options

By default, a modal closes on:
- A click on its close button
- A click outside the modal (on the backdrop)
- Escape. When a control inside the modal is open (a combobox, dropdown menu, multiselect, datepicker or `pds-popover` with `popover-type="auto"`), the first Escape closes only that control; the next Escape closes the modal.
- The browser's own close request, such as a back gesture on Android.

To have a control of your own take Escape, call `preventDefault()` on the Escape `keydown` from a listener on that control, and the modal stays open (see [Technical Notes](#technical-notes)).

`backdrop-dismiss` (default `true`) controls whether the modal can be dismissed by clicking outside it, pressing Escape, or the browser's own close request (such as a back gesture).

```html
<!-- Non-dismissible modal: backdrop clicks, Escape and the browser's close request are all ignored -->
<pds-modal backdrop-dismiss="false">
  <!-- Modal content that can only be closed via explicit button clicks -->
</pds-modal>
```

> **Note:** While WAI-ARIA guidelines recommend Escape-to-close for standard modals, setting `backdrop-dismiss="false"` disables this for use cases requiring explicit user action (e.g., required onboarding flows, critical confirmations). Ensure users have a clear, accessible path to complete the required action.

### Sizes

Modals come in four preset sizes, or a custom width:
- `sm` (520px) - For simple confirmations or short forms
- `md` (700px) - Default size, suitable for most use cases
- `lg` (900px) - For complex forms or detailed content
- `fullscreen` - Takes up the entire viewport

#### Custom Width

For a width outside the presets, pass a CSS length to `size`. It becomes the modal's `max-width`, so the modal still narrows to fit smaller screens. Lengths, `calc()`, `min()` and `clamp()` work; keywords such as `none` or `auto` don't.

A value that is neither a preset nor a valid CSS length (a typo like `xl`, for example) falls back to `md` and logs a console warning.

Custom widths are a code-only option: the Figma component has the preset sizes only, so a custom-width modal won't match a Figma variant.

### Overlays Above the Modal

By default a modal opens with the native `dialog.showModal()`, which promotes it to the browser [top layer](https://developer.mozilla.org/en-US/docs/Glossary/Top_layer). Nothing outside the dialog can paint above the top layer &mdash; not even with a higher `z-index` &mdash; so an overlay mounted elsewhere in the DOM (a file picker, a rich-text editor menu, a third-party widget appended to `document.body`) renders _behind_ the modal and becomes unreachable.

Set `disable-top-layer` to open the modal as a non-modal dialog (`dialog.show()`) in the normal stacking context instead. Overlays with a higher `z-index` can then display above it. A lone `disable-top-layer` modal sits at `--pine-z-index-modal` (6000), and one nested inside another modal at `--pine-z-index-priority` (8000), so an overlay needs a `z-index` above the tier of the modal it stacks over, such as `calc(var(--pine-z-index-modal) + 1)` over a lone modal. In the demo below, a button appended to `document.body` stands in for that overlay.

> **Note:** This mode is for letting a higher-`z-index` overlay (a file picker, an editor menu) appear _above_ the modal &mdash; not for making the modal itself non-blocking. The dimming backdrop still covers the page and an outside click still dismisses it (unless `backdrop-dismiss="false"`). What changes: the page is **not** made `inert` and **focus is not trapped**, so controls in an overlay stacked above the modal stay reachable by keyboard and assistive tech (which is why `aria-modal` is `false` in this mode). Escape closes the modal while focus is inside it; when an overlay above the modal owns focus, Escape is left to that overlay so it can close itself. A modal taller than the viewport scrolls the same way in both modes, so its footer stays reachable. One caveat: because the dialog now participates in normal stacking, a page element with its own higher stacking context can overlap it.

## Technical Notes

- The component renders a native `<dialog>` with `aria-labelledby="{component-id}-heading"`, so give the heading in the modal header that id (for example `<pds-text tag="h2" id="{component-id}-heading">`) for assistive technologies to announce the dialog by name. `aria-modal` is `true` by default and `false` when `disable-top-layer` is set (a non-modal dialog).
- Focus trapping is managed internally. When `open` becomes `true`, the component stores the previously focused element, queries for focusable nodes inside the modal, and moves focus to the first match. When `hideModal()` is called (directly or indirectly), focus is restored to the element that opened the modal. If that element is gone or can't take focus (disabled or hidden), focus goes to the first control of the open modal now on top, as long as that modal is in the top layer or wraps the one that closed; otherwise the page isn't inert, so focus is left where the browser puts it. In `disable-top-layer` mode focus is still placed on open but **not** trapped, so it can move to overlays stacked above the modal.
- Set `disable-initial-focus` for a modal that can open from a background event while the user is mid-task elsewhere on the page, so opening it doesn't move their focus. Pair it with `disable-top-layer`: in the top layer the rest of the page is inert, so focus can't stay there. On close, focus moves back only if nothing outside the modal has taken it.
- Backdrop clicks and Escape close only the top-most open modal: a modal inside another before the one around it, then a top-layer modal before one outside it. In the top layer, the one opened last wins (a modal inside a top-layer modal ranks with it). Among modals in the same layer, the higher backdrop `z-index` wins, then the one later in the page. So a confirm prompt opened from a modal closes before that modal does.
- The modal handles Escape from a plain `keydown` listener on `document`. A listener on your own control, or a capture listener (`capture: true`) on `document` or `window`, runs before it, so calling `preventDefault()` there keeps the modal open. A plain listener on `window` runs after it and is too late. Whether a plain listener on `document` runs first depends on whether it was added before the modal joined the page, so use a capture listener instead. `pds-popover` is a special case: it listens on `document`, and works only because the modal checks for an open auto popover inside it and leaves Escape alone. Don't copy its pattern. A manual popover leaves Escape to the modal. Only take Escape when your control actually closes something, or Escape will seem to do nothing.
