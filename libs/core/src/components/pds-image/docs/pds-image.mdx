# Image

An image can be used to convey supplemental information to the user or as decoration.

## Guidelines

### When to use

- Images that carry information, such as a product photo, a screenshot or a chart.
- Illustrations that support the text around them.

### When not to use

- Icons: use `pds-icon`.
- A person's or account's profile photo: use `pds-avatar`.
- Purely decorative backgrounds: use a CSS `background-image` on the containing element.

### Accessibility

- Always set `alt`. Leaving it out is the same as `alt=""`, which marks the image as decorative and hides it from screen readers.
- Describe what the image shows in the context where it appears. Set `alt=""` on purpose only when the image is purely decorative. For help deciding, see the W3C [alt decision tree](https://www.w3.org/WAI/tutorials/images/decision-tree/).

## Sizing and cropping

A surface that needs every image to hold the same shape should say so with `ratio` rather than sizing its own box, so the shape is stated once and the component handles the crop. `ratio` takes a preset — `square` (1 / 1), `landscape` (4 / 3), `wide` (16 / 9), `portrait` (3 / 4), `tall` (9 / 16) — or any custom CSS ratio, such as `21 / 9`.

Uploaded images rarely arrive in the shape a layout wants, so `fit` decides what happens to the part that does not fit. `cover`, the default, fills the shape and crops the overflow; use it for photographic content such as a hero or a thumbnail, where losing the edges is acceptable. `contain` scales the whole image down until it fits, leaving space around it; use it for content that must be seen in full and must not be cropped, such as a logo. Avoid `fill`, which stretches the image to the shape and distorts it.

`height` and `width` do not set a shape, and neither crops: once the image loads it keeps its own proportions, so a `height` and `width` that disagree with the image are not honored. Only `width` reserves that space before the image loads — `height: auto` lets the loaded image's own proportions decide the height, so `height` reserves nothing. To crop to a box of a given size, set `ratio` to that box's proportions, such as `ratio="4 / 1"`; with `ratio` set, the container decides the image's size and the `width`/`height` attributes have no effect. `fit` has no effect unless `ratio` is set.

There are two routes to a shape, and both crop: the `ratio` prop and the `--dimension-aspect-ratio` custom property. The prop wins over the custom property, and when it is in effect `fit` decides the crop instead of `--dimension-object-fit`.

**This is a behaviour change for images already sized by the custom property.** Until now a shape was applied with no `object-fit`, so the image stretched to fill it — the defect behind reports of distorted logos. Those images now crop instead. An image whose box already matches its own proportions is unaffected, since it has no overflow to crop. Where an image must be seen whole rather than cropped, set `--dimension-object-fit: contain`, or move it to the `ratio` prop and set `fit="contain"`.

To reserve the image's full box before it loads, pair `width` with `--dimension-aspect-ratio` set to the image's own proportions, such as `width="200"` and `--dimension-aspect-ratio: 2 / 3` for a 200 × 300 image. The shape matches the image, so nothing is cropped. An image with `ratio` set reserves its box too, at the width of its container.

## Responsive images

The `srcset` and `sizes` props pass through to the native `<img>`, so the browser can choose a file for the viewport and screen. `srcset` lists the same image at several widths, all in the same aspect ratio, and `sizes` tells the browser how wide the image displays at each viewport size. A file in a different shape changes the image's height depending on which file the browser picks. When you set `sizes`, give every `srcset` candidate a width (`w`) descriptor: a list that mixes descriptor types is invalid HTML. For more information, see the MDN article on [responsive images](https://developer.mozilla.org/en-US/docs/Learn/HTML/Multimedia_and_embedding/Responsive_images).

### Image Optimization

While images can provide useful information to convey to the user, when not careful, they can also increase page load times, sometimes by several seconds. For users with slower internet connections, this can lead to a poor user experience. Be mindful that the images used are optimized in their file size. Unless using images with transparency, formats like `.jpg` can help naturally reduce file size. If needed, consider using a tool to further reduce the image's size.

### Sizes and Srcset

An image with `srcset` and `sizes` props set. At a viewport 450px wide or narrower, `sizes` says the image displays at 150px, so a standard-density screen loads the 150px file. Wider viewports, and high-density screens, load the 600px file. To see the switch, make the viewport 450px wide or narrower and reload. Both files are 3:1, but the placeholder service returns a different photo at each size; in your own `srcset`, list one image at several widths.

<DocCanvas

<PdsImage

  src="https://placebear.com/600/200"
  srcset="https://placebear.com/150/50 150w, https://placebear.com/600/200 600w"
></PdsImage>

<pds-image

### Aspect Ratio

An image given a `ratio` fills the width it is given and takes its height from the shape. The source here is portrait (`200x300`) while the shape is `wide`, so the overflow is cropped instead of the image being squashed into the shape.

<DocCanvas
  mdxSource={{
    react: '<PdsImage src="https://placebear.com/200/300" alt="Random Bear" ratio="wide"></PdsImage>',

}}>
  <div style={{ width: '320px' }}>
    <pds-image src="https://placebear.com/200/300" alt="Random Bear" ratio="wide"></pds-image>
  </div>
</DocCanvas>
