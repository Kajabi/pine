# Checkbox

Checkboxes provide users with selectable options like toggling a single setting or selecting multiple options from a list.

## Guidelines

### When to use
- Use checkboxes when users can select one or more options from a set.
- Ideal for situations where multiple selections can be made.

### When not to use
- Avoid using checkboxes for single-choice selections, such as in forms where only one option should be selected. In such cases, consider using radios or a switch.

### Accessibility
- Provide a clear, descriptive label for each checkbox to ensure that screen readers can identify the option effectively.
- The `aria-describedby` attribute is used to associate the checkbox with an error message or helper message but may not be read out by all screen readers.
- Put only non-interactive content in the `label` slot. Buttons and links inside a label are invalid HTML.
- State classes on the host (such as `is-invalid` and `is-disabled`) follow the component's props, and `has-label-slot` follows the `label` slot's content. They come back if something removes them, such as a DOM morph, so change them through props or the slot. A script that undoes them as soon as they come back (from a `MutationObserver`, say) wins after a few rounds, and the component logs a console warning.

### Label slot

Use the `label` slot when the label needs more than text, such as a `pds-chip`. Clicking the slotted content toggles the checkbox, and its text becomes the checkbox's accessible name. Without slotted content, the `label` prop renders as usual.

### Pill

Set `variant="pill"` to render the checkbox as a pill-shaped choice for picking several short options. The checkbox square is visually hidden and the label becomes the pill, so the input is still a native checkbox: Space toggles it, it submits with the form, and screen readers announce it as a checkbox. Checking a pill adds an inset ring instead of a thicker border, so the pill doesn't change size. The focus ring shows for keyboard focus only. A pill always shows its label, so `hideLabel` is ignored. `invalid` turns the pill's border red; `indeterminate` has no pill style.

Wrap related pills in a `fieldset` with a `legend` so the group has a name, and lay them out in a wrapping row.

## Events

### pdsCheckboxChange
Used when you want to perform an action when the checkbox state changes. The returned structure is a `CheckboxChangeEventDetail` that contains `checked` and `value`.

## Form Integration

- Set the `name` attribute so each checked box contributes its `value` to `FormData`; unchecked boxes are omitted automatically.
- Give every checkbox in a group a distinct `value` so the server can differentiate selections.
- Pair `required`, `invalid`, and `errorMessage` when you need inline validation.
