# Tabs

Tabs organize related content into separate panels that users switch between using a horizontal button bar, keeping only one panel visible at a time.

## Guidelines

### When to use

- To switch between longer, related views of one topic without leaving the page, such as a course's overview, lessons and settings.
- With `nav`, for links to sibling pages that should look like tabs, such as the sections of an account area. See [Navigation tabs](#navigation-tabs).

### When not to use

- For short, independent sections, or on narrow screens with little room. Use [Accordion](/docs/components-accordion--docs) instead.
- When the labels are long. Use an accordion instead.
- For links to other pages without `nav`. Panel tabs switch content on the same page.

### Accessibility

Give every `pds-tabs` a unique `component-id` and a `tablist-label` that describes the set of tabs, such as "Course sections". The label is the accessible name of the tab list, or of the `<nav>` landmark in navigation mode, so never leave a placeholder there.

Each tab's `name` must be unique among the tabs and contain no spaces, and each panel's `name` must match its tab's. The `component-id` and `name` build the ids that link each tab to its panel, and a space breaks that link for screen readers.

Keyboard support in panel mode:

- `Tab` moves focus to the selected tab. The other tabs are left out of the Tab order.
- `Left Arrow` and `Right Arrow` select the previous or next tab and show its panel, wrapping from the last tab to the first and back.
- `Home` and `End` select the first and last tab.
- `Tab` from the selected tab moves focus to its panel, then into the panel's content.

In navigation mode, each tab is a link: `Tab` moves between the links, `Enter` follows one, and the arrow keys do nothing.

Without `active-tab-name`, the first enabled tab starts active. In `nav` mode, set `active` on the current tab instead.

`pds-tabs` emits no event when the active tab changes. Its `active-tab-name` attribute changes instead, whether a reader clicks a tab or uses the arrow keys, or you set `active-tab-name` in code. To react to a change, watch that attribute:

```javascript
const tabs = document.querySelector('pds-tabs[component-id="course"]');

new MutationObserver(() => {
  console.log(tabs.getAttribute('active-tab-name'));
}).observe(tabs, { attributes: true, attributeFilter: ['active-tab-name'] });
```

### Navigation tabs

Add `nav` to `pds-tabs` when each tab opens its own page. The tabs render as links inside a `<nav>` landmark, so give every `pds-tab` an `href`, set `active` on the tab for the current page, and leave out `pds-tabpanel`. Use `href` on all of the tabs or none: the console warns when `nav` is set and a tab has no `href` attribute, or when a tab has an `href` attribute without `nav`. A tab with `target="_blank"` also gets `rel="noopener noreferrer"`.

<DocCanvas mdxSource={{

  <PdsTab name="help" href="https://help.example.com" target="_blank">Help</PdsTab>
</PdsTabs>

### Stretch

The `stretch` prop makes the component fill its container's height, for tab sets inside a height-bounded region (a rail, a modal body, a split-pane column). The active panel doesn't grow to fill the space below the tab list, and it doesn't scroll on its own: it keeps the height of its content, so taller content overflows the region. To scroll long content, wrap it in your own container with a fixed height (such as `max-block-size`) and `overflow: auto`. Give the parent a fixed height for the effect to show.
