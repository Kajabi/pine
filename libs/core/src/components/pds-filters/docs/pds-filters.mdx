# Filters

Filters are a row of popover triggers for narrowing a set of data. The `pds-filters` container lays out the row, and each `pds-filter` child holds the controls for one filter.

## Guidelines

### When to use

- When users need to filter or search through data sets
- For interfaces that require multiple filter options
- When you need custom content within filter popovers
- For creating clear/reset filter functionality

### When not to use

- For simple single-select dropdowns (use [Select](/docs/components-select--docs))
- For navigation menus (use [Dropdown Menu](/docs/components-dropdown-menu--docs))
- For single action buttons (use [Button](/docs/components-button--docs))

### Accessibility

- Always set `text`. The trigger's icons are hidden from screen readers, so a filter without `text` has no accessible name, and an `aria-label` on `pds-filter` doesn't reach the trigger.
- The `selected` variant changes only how the trigger looks. Put the applied value in `text`, such as "Status: Published", so screen reader users hear which filters are on.
- Give every control in the popover a label, such as `pds-checkbox`'s `label`.
- The trigger is a button that reports `aria-expanded`, so screen readers announce it as collapsed or expanded. It doesn't announce a menu or a dialog, because the popover is neither. The `clear` trigger opens nothing, so it's a plain button with no expanded state.
- Enter or Space opens and closes the popover. Focus stays on the trigger when the popover opens, and Tab moves into the popover's controls. Tabbing past the last control moves on to the next filter and leaves the popover open.
- Escape closes the popover and leaves focus on the trigger, whether it was pressed on the trigger or on a control inside the popover. Opening one filter closes any other open filter.
- If your code moves focus to another element when the popover closes, such as in a `pdsFilterClose` listener, focus stays on that element.

The markup alone doesn't update the triggers. A script like this one does: when a filter closes, it shows the checked options in `text` and switches to `selected`, and the clear filter unchecks everything.

```javascript
const bar = document.querySelector('pds-filters');

bar.addEventListener('pdsFilterClose', (event) => {
  const filter = event.target;
  const label = filter.dataset.label;
  if (!label) return;
  const picked = Array.from(filter.querySelectorAll('pds-checkbox'))
    .filter((checkbox) => checkbox.checked)
    .map((checkbox) => checkbox.label);
  filter.variant = picked.length ? 'selected' : 'default';
  filter.text = picked.length ? `${label}: ${picked.join(', ')}` : label;
  // Filter your data by the checked values.
});

bar.addEventListener('pdsFilterClear', () => {
  bar.querySelectorAll('pds-checkbox').forEach((checkbox) => {
    checkbox.checked = false;
  });
  bar.querySelectorAll('pds-filter[data-label]').forEach((filter) => {
    filter.variant = 'default';
    filter.text = filter.dataset.label;
  });
  // Show your data unfiltered.
});
```

In React, keep the checked options in state, render each checkbox's `checked` and each filter's `variant` and `text` from that state, and empty it in the clear filter's `onPdsFilterClear`.

## Events

Each `pds-filter` emits its own events, and they bubble, so one listener on `pds-filters` hears every filter, as in [Filter bar](#filter-bar). The `pds-filter` properties table above says when each event fires and what its `detail` holds.

## Methods

### showFilter()

Opens the filter popover programmatically. Clear variant will log a warning if this method is called.

### hideFilter()

Closes the filter popover programmatically. Clear variant will log a warning if this method is called.
