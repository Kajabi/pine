# Sortable

Sortable is for creating containers of items that can be sorted by dragging or from the keyboard.

## Guidelines

### When to use
- Use the `sortable` component when you need to create an interface for reordering items, by dragging or from the keyboard.
- Ideal for situations where users need to arrange content dynamically.

### When not to use
- Avoid using for small lists or static content where drag-and-drop functionality is unnecessary.
- Not suitable for forms or content that does not require item reordering.

### Accessibility

Every item can be reordered from the keyboard as well as by dragging, so the list meets WCAG 2.1.1 (Keyboard).

WCAG 2.5.7 (Dragging Movements, 2.2 AA) also asks for a way to reorder with single pointer clicks, which the keyboard doesn't give. Where you need it, put "Move up" and "Move down" buttons in the `sortable-item-actions` slot and reorder your data when they're pressed.

- **What gets focus:** each item's handle is a tab stop: a button labelled "Reorder" plus the item's name, that's pressed while the item is picked up. Without `show-handle`, the handle is hidden but still there for the keyboard, and the row shows its focus ring. A pointer still drags the whole row with `handle-type="row"`. Controls inside a row, such as its actions, keep their own keys.
- **Screen readers:** pressing the handle in a screen reader's browse mode picks the item up and drops it too. Moving it with the arrow keys needs the screen reader's focus (forms) mode, such as NVDA+Space or JAWS's Enter on the button, so the "Move up" and "Move down" buttons above are the most dependable path for screen reader users.
- **The item's name:** the handle's label and the announcements use the item's text, leaving out the handle and the actions. Set `item-label` on a `pds-sortable-item` when that text is long, isn't a good name, or changes after the item renders.
- **Announcements:** a polite live region announces when an item is picked up, each move ("Item 2, moved to position 3 of 7"), and the drop or cancel. The live region is placed right after the list, not among its items, so it's never counted as an item and is still announced inside a modal.
- **Events:** a keyboard drop emits `pdsSortableItemMoved` with the same detail fields as a drag (`item`, `from`, `to`, `oldIndex`, `newIndex`, `oldDraggableIndex`, `newDraggableIndex`), so a save handler works for both. Escape emits nothing.
- **Focus:** focus stays on the moved item the whole time, and the item scrolls into view as it moves. Moving focus elsewhere on the page drops it where it is. Switching to another window keeps it picked up.
- **Disabled:** a `disabled` list has no tab stops, and disabling it puts a picked-up item back. A pointer drag that starts while an item is picked up drops it first.
- **Direction and motion:** only the Up and Down arrows move an item, so right-to-left layouts work the same way. With `prefers-reduced-motion: reduce`, dragged items don't animate into place and the picked-up state doesn't fade.

#### Localization

The handle's label and the announcements are props on `pds-sortable`, with English defaults. Pass translated strings to localize them: `handle-label`, `item-picked-up-label`, `item-moved-label`, `item-dropped-label` and `reorder-canceled-label`. `{item}`, `{position}` and `{total}` are filled in. Their English defaults are in the properties table below, and the Localized example shows them in French.

## Technical Notes

The component keeps the classes it puts on its host. If something removes them, such as a DOM morph, it puts them back, so change its layout through props. Classes you add yourself are left alone. A script that undoes them as soon as they come back (from a `MutationObserver`, say) wins after a few rounds, and the component logs a console warning.
