# Sortable

Sortable is for creating containers of items that can be sorted by dragging or from the keyboard.

## Guidelines

### When to use
- Use the `sortable` component when you need to create an interface for reordering items, by dragging or from the keyboard.
- Ideal for situations where users need to arrange content dynamically.

### When not to use
- Avoid using for small lists or static content where drag-and-drop functionality is unnecessary.
- Not suitable for forms or content that does not require item reordering.

### Accessibility

- Every item can be reordered from the keyboard as well as by dragging, so the list meets WCAG 2.1.1 (Keyboard). Each item's handle is a reorder button named after the item; see [Keyboard interactions](#keyboard-interactions).
- WCAG 2.5.7 (Dragging Movements, 2.2 AA) also asks for a way to reorder with single pointer clicks, which the keyboard doesn't give. Where you need it, set `enable-actions`, put "Move up" and "Move down" buttons in the `sortable-item-actions` slot, and reorder your data when they're pressed. They're also the most dependable way for screen reader users to reorder, as the arrow keys need the screen reader's focus mode.
- The handle's label and the announcements name each item by its text. Set `item-label` when that text isn't a good name; see [Localization](#localization).
- `pds-sortable` doesn't set `role="list"`. If you set it, give each `pds-sortable-item` `role="listitem"` too, not just its content; otherwise axe flags the handle's `role="button"` as a child the list doesn't allow.
- A polite live region announces when an item is picked up, each move, and the drop or cancel.
- If your code replaces a row's element, such as by re-rendering it from a server response after `pdsSortableItemMoved`, focus is lost along with the old handle. Keep the existing row element across the update, or move focus to the new row's handle afterward.
- With `prefers-reduced-motion: reduce`, dragged items don't animate into place and the picked-up state doesn't fade.

### Saving the new order

When an item is dropped, `pdsSortableItemMoved` fires with its position before and after the move in `detail.oldIndex` and `detail.newIndex`, counted from 0. The list has already moved the item by then, so the page shows the new order. A drag emits the event on every drop, even one that ends where it started, so check that the two indexes differ before you save. A keyboard drop emits it only when the position changed (see [Keyboard interactions](#keyboard-interactions)).

Read the new order from the list's items:

```javascript
const list = document.querySelector('pds-sortable[component-id="lessons"]');

list.addEventListener('pdsSortableItemMoved', (event) => {
  const { oldIndex, newIndex } = event.detail;
  if (oldIndex === newIndex) return;
  const order = Array.from(list.children, (item) => item.dataset.id);
  // Save the new order, such as by sending it to your server.
});
```

In React, render the items from state with a stable `key`, and move the item in state with the same two indexes. React then renders the order the list already shows.

```jsx
import { useState } from 'react';
import { PdsSortable, PdsSortableItem } from '@pine-ds/react';

export function LessonOrder({ initialLessons }) {
  const [lessons, setLessons] = useState(initialLessons);

  const handleMoved = (event) => {
    const { oldIndex, newIndex } = event.detail;
    if (oldIndex === newIndex) return;
    setLessons((current) => {
      const next = [...current];
      const [moved] = next.splice(oldIndex, 1);
      next.splice(newIndex, 0, moved);
      return next;
    });
  };

  return (
    <PdsSortable componentId="lessons" onPdsSortableItemMoved={handleMoved}>
      {lessons.map((lesson) => (
        <PdsSortableItem key={lesson.id}>{lesson.title}</PdsSortableItem>
      ))}
    </PdsSortable>
  );
}
```

- **The handle:** every item's handle is a tab stop, with or without `show-handle`. It's a button named by `handle-label` ("Reorder" plus the item's name), pressed while its item is picked up. Without `show-handle`, the handle is visually hidden and the row shows the focus ring instead. A `disabled` list has no tab stops, and disabling it puts a picked-up item back.
- **The row:** with `handle-type="row"`, a pointer still drags the whole row. Controls inside a row, such as its actions, keep their own keys. `pointer-events: none` on a row doesn't take its handle out of the tab order, so a keyboard user can still Tab to it and reorder that row.
- **Moving:** only the Up and Down arrows move an item, so right-to-left layouts work the same way. Focus stays on the picked-up item's handle, and the item scrolls into view as it moves. Each move is announced, such as "Item 2, moved to position 3 of 7"; at the first or last position, a key that can't move it further repeats the current position instead of staying silent.
- **Dropping:** besides Space or Enter, moving focus anywhere else on the page drops the item where it is, and so does a click or touch in the list, so a drag starts from the new order. Switching to another window keeps it picked up.
- **Events:** a keyboard drop emits `pdsSortableItemMoved` with the same detail fields as a drag (`item`, `from`, `to`, `oldIndex`, `newIndex`, `oldDraggableIndex`, `newDraggableIndex`), so one save handler works for both. Unlike a drag, it emits nothing when the item ends where it started, and Escape emits nothing either.
- **Screen readers:** in a screen reader's browse mode, pressing the handle picks the item up, and pressing it again drops it. The arrow keys reach the handle only in the screen reader's focus (forms) mode.

## Localization

The handle's label and the announcements are props on `pds-sortable`, with English defaults, shown in the properties table. Pass translated strings to localize them: `handle-label`, `item-picked-up-label`, `item-moved-label`, `item-dropped-label` and `reorder-canceled-label`. `{item}` is filled in for all five; `{position}` and `{total}` only for the four announcements, not `handle-label`, which has no position to fill them with. The [Localized](#localized) example shows them in French.

`{item}` is the item's `item-label`, or else the text of its first child that has any, leaving out the handle and the actions. Set `item-label` on a `pds-sortable-item` when that text is long or isn't a good name, or when it changes after the item renders: the announcements read the current text, but the handle's label doesn't follow a change to it.

## Technical notes

The component keeps the classes it puts on its host. If something removes them, such as a DOM morph, it puts them back, so change its layout through props. Classes you add yourself are left alone. A script that undoes them as soon as they come back (from a `MutationObserver`, say) wins after a few rounds, and the component logs a console warning.

The announcements go to a visually hidden live region that the list adds right after itself, not among its items. So the list's children are only its items, and the announcements still reach a screen reader when the list is inside a modal.
