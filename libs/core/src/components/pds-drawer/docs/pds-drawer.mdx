# Drawer

Drawers are side panels that open beside the page, which stays interactive by
default. Add `modal` for a drawer the page should wait on (see [Modal](#modal)).

Unlike `pds-modal`, a default drawer doesn't dim or blur the page or block
clicks.

`pds-drawer` composes `pds-modal` internally and inherits its focus-return,
Escape and dialog semantics unchanged. It adds the edge, width and dismiss
behavior a side panel needs.

## Guidelines

### When to use

- For a panel people work in beside the page, such as settings or the details of a selected item
- When people need to see or use the page while the panel is open

### When not to use

- For a short task that blocks the page, such as a confirmation or a focused form (use [Modal](/docs/components-modal--docs)). For a longer blocking task that suits a side panel, add `modal` (see [Modal](#modal)).
- For a short explanation or a few options tied to one control (use [Popover](/docs/components-popover--docs))

### Accessibility

- Name the drawer: its dialog is labelled by the element with the id `{component-id}-heading`, modal or not, so give the drawer's heading that id.
- A drawer moves focus to its first control when it opens, unless it's non-modal with `initial-focus="none"`.
- In a non-modal drawer, Tab isn't trapped, so focus moves freely between the drawer and the page. A `modal` drawer keeps focus inside it and makes the page inert.
- Escape closes a non-modal drawer from anywhere on the page, not only from inside it. It doesn't when focus is in a dialog or overlay stacked above the drawer, or when an open control, such as a dropdown menu, closes on that Escape first.
- When the drawer closes with focus inside it, focus returns to the control that opened it. When it closes from the page (Escape, or a click outside), focus stays where it is.

### Subcomponents

- `pds-drawer-header` lays out its content in a padded row, with the title and close control spaced apart and a divider below.
- `pds-drawer-content` fills the space between the header and footer, adds padding, and scrolls when `scrollable` is on.
- `pds-drawer-footer` lays out its actions in a padded row aligned to the end, with a divider above.

Unlike the modal's subcomponents, these add their own padding and layout, so their content needs no `pds-box` wrapper.

## Usage

```html
<pds-drawer open component-id="automation-settings" side="end" size="md">
  <pds-drawer-header>
    <pds-text tag="h2" size="h4" id="automation-settings-heading">Automation settings</pds-text>
  </pds-drawer-header>
  <pds-drawer-content>…</pds-drawer-content>
  <pds-drawer-footer>…</pds-drawer-footer>
</pds-drawer>
```

- A trigger only sets `open` to `true`. The drawer closes itself (Escape, a
  click outside) and sets its own `open` to `false`, so listen for
  `pdsDrawerClose` to update your state. It can fire twice for one close, so
  keep its handler safe to run again. A toggle-style trigger
  (`open = !open`) fights light dismiss: clicking it while the drawer is open
  closes the drawer on `pointerdown`, then the trigger's own click handler
  opens it again.
- `size` sets the width: `sm` is 360px and `md` (the default) is 500px. On a
  narrower screen, the drawer fills the width.
- `side` is logical (`start` / `end`): `end` is the inline-end edge, so an
  `end` drawer docks on the left in right-to-left layouts.
- `light-dismiss` (default `true`): a default drawer has no backdrop to click,
  so a pointerdown outside it closes it, from any mouse button or a touch.
  Pointerdowns in a `pds-modal` or in a popover, tooltip or combobox panel
  don't count as outside, and moving focus out with the keyboard doesn't close
  it. A `modal` drawer closes on a click on its backdrop instead.
- `light-dismiss="false"` turns off outside clicks and Escape, so keep a close
  button in the drawer.
- `initial-focus="none"` opts out of moving focus into the drawer on open —
  use it for a drawer that can open from a background event while the user
  is mid-task elsewhere on the page.

## Modal

A drawer is non-modal by default: people keep working on the page beside it.
For a task the page should wait on, such as building filters before applying
them, add `modal`. A modal drawer dims the page with a backdrop, makes the page
inert, and keeps focus inside the drawer, like `pds-modal`. It still docks to
its `side` at its `size`.

- Always include a close control. With `light-dismiss="false"`, Escape and the
  backdrop don't close it, so the close control is the only way out.
- `modal` is read when the drawer opens. Set it before opening, not while open.
- `initial-focus="none"` doesn't apply: focus starts in a modal drawer.
- Tooltips and popovers inside a modal drawer open inside it and show above
  it. A tooltip opened with `opened` before the drawer opens stays behind the
  drawer until the tooltip opens again.

```html
<pds-drawer open modal component-id="contact-filters" side="end" size="md">
  <pds-drawer-header>
    <pds-text tag="h2" size="h4" id="contact-filters-heading">Filters</pds-text>
  </pds-drawer-header>
  <pds-drawer-content>…</pds-drawer-content>
  <pds-drawer-footer>…</pds-drawer-footer>
</pds-drawer>
```
