# Contributing

Contributions to Pine are welcome, whether you're fixing a bug, improving documentation or proposing a new component. Pine is maintained by its contributors, with no assigned stewards. The `@Kajabi/dss-devs` code owners review pull requests, and each one needs two approving reviews before it merges.

The full guide is <pds-link href="https://github.com/Kajabi/pine/blob/main/CONTRIBUTING.md" external>CONTRIBUTING.md</pds-link> in the repository, so it stays in step with the code. It covers:

- Local setup: the Node version, local certificates for the dev server, and running Storybook
- Branch names and commit messages, which git hooks check when you commit and push
- Generating a component, and writing its docs so the Pine MCP can read them
- The checks every pull request runs: lint, spec and end-to-end tests, bundle size budgets, public API reports, the accessibility gate and visual regression
- How releases are cut

Before you change a component's public API, read <pds-link href="https://github.com/Kajabi/pine/blob/main/VERSIONING.md" external>VERSIONING.md</pds-link>. It defines what counts as a breaking change and how to deprecate a prop, event or method. Significant, long-lived decisions are recorded as <pds-link href="https://github.com/Kajabi/pine/blob/main/docs/adr/README.md" external>Architecture Decision Records</pds-link>.

Pine is built with <pds-link href="https://stenciljs.com/" external>Stencil</pds-link>, so it helps to know how web components and Stencil work before you change a component.

For questions, see <pds-link href="../?path=/docs/introduction-get-support--docs">Get Support</pds-link>.
