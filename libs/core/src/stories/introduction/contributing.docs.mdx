# Contributing

Contributions to Pine are welcome, whether you're fixing a bug, improving documentation or proposing a new component. Pine is maintained by its contributors, with no assigned stewards. The `@Kajabi/dss-devs` code owners review pull requests, and each one needs one approving review before it merges.

The full guide is [CONTRIBUTING.md](https://github.com/Kajabi/pine/blob/main/CONTRIBUTING.md) in the repository, so it stays in step with the code. It covers:

- Local setup: the Node version, local certificates for the dev server, and running Storybook
- Branch names and commit messages, which git hooks check when you commit and push
- Generating a component, and writing its docs so the Pine MCP can read them
- The checks every pull request runs: lint, spec and end-to-end tests, bundle size budgets, public API reports, the accessibility gate and visual regression
- How releases are cut

Before you change a component's public API, read [VERSIONING.md](https://github.com/Kajabi/pine/blob/main/VERSIONING.md). It defines what counts as a breaking change and how to deprecate a prop, event or method. Significant, long-lived decisions are recorded as [Architecture Decision Records](https://github.com/Kajabi/pine/blob/main/docs/adr/README.md).

Pine is built with [Stencil](https://stenciljs.com/), so it helps to know how web components and Stencil work before you change a component.

For questions, see [Get Support](/docs/introduction-get-support--docs).
