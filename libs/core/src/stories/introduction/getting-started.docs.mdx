# Getting Started

Welcome to Pine. This guide gets you up and running quickly, whether you're a designer or a developer.

---

## For Designers

### 1. Access the Figma library

Pine's component library and token set are maintained in Figma. Request access through <pds-link href="https://kajabi.slack.com/archives/C01A424HY8Y" external>#ds-support</pds-link> if the library isn't already enabled in your Figma workspace.

### 2. Use Pine tokens

All spacing, color, and typography values in Figma are backed by Pine design tokens. Use token-named styles (e.g. `color/background/container`) rather than raw hex values so your designs stay in sync with the coded components.

See <pds-link href="../?path=/docs/design-tokens-tokens--docs">Design Tokens</pds-link> for the full token reference.

### 3. Map designs to component docs

Every Pine component has a Storybook doc page with usage guidelines, prop options, and live examples. Reference these when specifying designs to ensure what you're handing off is buildable with existing components.

Browse components in the **Components** section of the sidebar.

### 4. Request components or file issues

If a component you need doesn't exist or a token is missing, <pds-link href="https://github.com/Kajabi/pine/issues/new/choose" external>open a GitHub issue</pds-link> with the Feature request template. Kajabi staff can also ask in <pds-link href="https://kajabi.slack.com/archives/C01A424HY8Y" external>#ds-support</pds-link> (Kajabi-internal Slack).

### 5. Contribute

Designers can contribute to Pine too. See <pds-link href="../?path=/docs/introduction-contributing--docs">Contributing</pds-link> for the process.

## For Developers

### 1. Install Pine

**CDN (any page, no build step):** add these tags to `<head>`.

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@pine-ds/core@[VERSION]/dist/pine-core/pine-core.css" />
<script type="module" src="https://cdn.jsdelivr.net/npm/@pine-ds/core@[VERSION]/dist/pine-core/pine-core.esm.js"></script>
<script nomodule src="https://cdn.jsdelivr.net/npm/@pine-ds/core@[VERSION]/dist/pine-core/pine-core.js"></script>
```

Replace `[VERSION]` with an exact version from <pds-link href="https://github.com/Kajabi/pine/releases" external>GitHub Releases</pds-link>, not `latest`. See <pds-link href="https://github.com/Kajabi/pine/blob/main/VERSIONING.md#consumer-guidance" external>Consumer guidance</pds-link> for how to pin npm and CDN versions.

**React projects:**

```bash
npm install @pine-ds/react
```

`@pine-ds/react` registers each component you import, but it doesn't load Pine's stylesheet, `pine-core.css`, which defines the design tokens and loads the Inter font. Without it, components render with no Pine colors, in the browser's default font. The stylesheet can't be imported from the package, because the package's `exports` field doesn't list it. Load it one of these ways:

- Add the `<link>` tag from the CDN snippet above, with `[VERSION]` set to the `@pine-ds/core` version in your lockfile. `npm ls @pine-ds/core` prints it. You don't need the two `<script>` tags.
- Have your build copy `node_modules/@pine-ds/core/dist/pine-core/pine-core.css` into the files your app serves, and link to that copy.

**Other frameworks and bundlers:**

```bash
npm install @pine-ds/core
```

Import each component you use from the custom-elements build, and register it. Keep the `.js` at the end of the path. Registering a component also registers the components it renders, such as the `pds-icon` inside `pds-button`.

```js
import { defineCustomElement as definePdsButton } from '@pine-ds/core/components/pds-button.js';

definePdsButton();
```

Load the stylesheet the same way as in a React project.

### 3. Add an icon

`pds-icon` shows icons from `@pine-ds/icons`. In HTML, set the icon's `name`. In React, import the icon from `@pine-ds/icons/icons` and pass it to `icon`.

<DocCanvas
  mdxSource={{
    webComponent: `<pds-button><pds-icon slot="start" name="add"></pds-icon>Add item</pds-button>`,
    react: `import { add } from '@pine-ds/icons/icons';
import { PdsButton, PdsIcon } from '@pine-ds/react';

<PdsButton><PdsIcon slot="start" icon={add} />Add item</PdsButton>`
  }}>
  <pds-button><pds-icon slot="start" name="add"></pds-icon>Add item</pds-button>
</DocCanvas>

Find an icon's name in the `name` control on the <pds-link href="../?path=/docs/components-icon--docs">Icon</pds-link> page. A named icon loads its SVG at runtime, from jsDelivr unless you set an asset path. <pds-link href="../?path=/docs/resources-icon-management--docs">Icon Management</pds-link> explains where icons load from and how to pin them.

### 4. Style with tokens

Pine components use CSS custom properties (design tokens) internally. You can reference the same tokens in your own styles:

```css
.my-card {
  background-color: var(--pine-color-background-container);
  border-radius: var(--pine-border-radius-md);
  padding: var(--pine-dimension-md);
}
```

Tokens are available after the Pine CSS file is loaded. See <pds-link href="../?path=/docs/design-tokens-tokens--docs">Design Tokens</pds-link> for the full list.

### 5. Turn on dark mode

Set `data-theme="dark"` on `<html>` to switch the page to Pine's dark tokens:

```html
<html data-theme="dark">
```

Pine doesn't follow the operating system's setting on its own, and dark-mode support is still rolling out one component at a time. See <pds-link href="../?path=/docs/design-tokens-tokens--docs#dark-mode">Dark mode</pds-link> for what switches, the `color-scheme` setting to add, and the components whose dark styles depend on the browser.

### 6. Run Storybook locally

To browse components with live examples, run the Pine dev server:

```bash
npm run start
```

Storybook will open at `http://localhost:6006`. See <pds-link href="../?path=/docs/introduction-contributing--docs">Contributing</pds-link> for the full local setup steps.

## Common Gotchas

**Components not rendering?**
With the CDN, check that the page has the `<link>` and both `<script>` tags from step 1, with the same `[VERSION]` in each, and place them in `<head>`.

**Components render without Pine's colors or font?**
The page isn't loading `pine-core.css`. `@pine-ds/react` and the custom-elements build register components but don't load the stylesheet. Load it as step 1 shows.

**Components hidden after a DOM morph?**
A morph that makes a host match the server's HTML removes the host's `hydrated` class. Components the CDN build registers are hidden without that class, and the CDN build puts the class back on its own. Components registered by `@pine-ds/react` or the custom-elements build stay visible without it. On a page that loads both, each component follows the build that registered it first, and the CDN build puts the class back on all of them.

**Storybook hot reload breaks rendering?**
Re-run `npm run start`. Hot reload in Stencil dev mode can occasionally lose component registration.

**Tokens not resolving?**
Custom properties require the Pine stylesheet to be loaded in scope. Confirm your page loads `pine-core.css`, as step 1 shows.

**React prop names differ from web component attribute names?**
React wrappers use camelCase props (e.g. `hideLabel`) while web component attributes are kebab-case (e.g. `hide-label`). Refer to each component's **Properties** table for both.
