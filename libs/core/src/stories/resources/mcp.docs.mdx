# Pine MCP

The Pine MCP is a **Model Context Protocol (MCP) server** that provides AI assistants with intelligent access to the Pine Design System. It allows AI tools to understand and work with Pine components, design tokens, and best practices.

## What is Pine MCP?

Pine MCP bridges the gap between AI assistants and the Pine Design System by providing:

- **Component Discovery** - AI can find and understand all Pine components
- **Design Token Access** - Intelligent recommendations for colors, spacing, typography
- **Code Generation** - AI generates code that follows Pine guidelines
- **Validation** - Automatic checking of implementations against Pine rules
- **Documentation Access** - Access to Pine component docs and examples

Instead of AI assistants making up component names or using incorrect properties, they can query Pine MCP to get accurate information about what's actually available in the Pine Design System.

## Available Tools

Your assistant picks these tools itself; you don't call them by hand. Knowing them helps you read what it's doing and ask for the right one.

**Discover**

- `list_pine_components` - every Pine component, with a short description
- `list_pine_icons` - the icon set, searchable by name, tag or category
- `list_pine_patterns` - page-level composition recipes from the <pds-link href="../?path=/docs/resources-patterns--docs">Patterns</pds-link> page
- `list_pine_design_docs` - Pine's design docs, such as tokens, layout and forms

**Resolve**

- `get_pine_component` - one component's props, events, methods, slots, examples, guidelines and accessibility notes, as web components, React or both
- `get_pine_tokens` - design tokens with their resolved values, filtered by purpose or name
- `get_pine_pattern` - one composition recipe by id, as web components or React
- `get_pine_design_doc` - one design doc, or one section of it
- `ask_pine_agent` - answers a Pine question in plain language, with code examples

**Generate and validate**

- `get_pine_context_for_generation` - every blocking, warning and guidance rule, to read once before generating Pine code
- `validate_pine_layout` - checks markup against Pine's layout rules and returns each violation with a fix
- `validate_ui_generation` - runs the full validation workflow on generated UI and auto-fixes mobile-first violations

**Deprecated** (still available, to be removed in a future release): `review_generated_layout` (use `validate_pine_layout`), `fix_layout_issues` (use `validate_pine_layout` or `validate_ui_generation`) and `should_engage_pine_workflow` (call `get_pine_context_for_generation` before generating and `validate_ui_generation` after).

Clients that support MCP resources can also read `pine://components`, `pine://components/{componentName}`, `pine://tokens/semantic`, `pine://tokens/core` and `pine://icons`.

## Connect Your Assistant

Pine MCP is served over Streamable HTTP at `https://pine-mcp.netlify.app/mcp`.

### Identify Your Project

Pine MCP uses the `x-pine-mcp-client` header to tell callers apart, so usage and validation results from your project can be separated from everyone else's. Without it, your calls are grouped by the generic user agent of your tool (for example, `node` or `claude-code`).

- **Use a stable name per repo or app** - for example, `my-app`. Don't use spaces; an optional version can follow a slash (`my-app/1.2.0`).
- **Prefix test and verification runs with `test-`** - for example, `test-my-app`. These calls are kept out of the quality dashboards.

Replace `<your-repo-or-app-name>` in the examples below with your project's name.

### Claude Code

Add the server from your project's directory:

```bash
claude mcp add --transport http pine-mcp https://pine-mcp.netlify.app/mcp --header "x-pine-mcp-client: <your-repo-or-app-name>"
```

To share the server with everyone who works in the repository, add `--scope project`, which writes the entry to `.mcp.json` at the repository root for you to commit. You can also write the file by hand. The entry needs `"type": "http"`:

```json
{
  "mcpServers": {
    "pine-mcp": {
      "type": "http",
      "url": "https://pine-mcp.netlify.app/mcp",
      "headers": {
        "x-pine-mcp-client": "<your-repo-or-app-name>"
      }
    }
  }
}
```

### Cursor and Windsurf

Cursor reads `.cursor/mcp.json` in the project, or `~/.cursor/mcp.json` for every project. Windsurf reads its own `mcp_config.json` (see Windsurf's MCP documentation for its location). Both connect over HTTP directly:

```json
{
  "mcpServers": {
    "pine-mcp": {
      "url": "https://pine-mcp.netlify.app/mcp",
      "headers": {
        "x-pine-mcp-client": "<your-repo-or-app-name>"
      }
    }
  }
}
```

### Visual Studio Code

VS Code's MCP support needs `"type": "http"` on the server entry. Its config file and top-level key have changed between releases, so follow <pds-link href="https://code.visualstudio.com/docs/copilot/reference/mcp-configuration" external>VS Code's MCP configuration guide</pds-link> for where the entry goes, and use:

```json
{
  "pine-mcp": {
    "type": "http",
    "url": "https://pine-mcp.netlify.app/mcp",
    "headers": {
      "x-pine-mcp-client": "<your-repo-or-app-name>"
    }
  }
}
```

### Claude Desktop

Claude Desktop's config file starts local servers, so it reaches Pine MCP through the `mcp-remote` proxy. Open the file from **Settings → Developer → Edit Config**, add the server, and restart Claude Desktop. `mcp-remote` sends the header through its `--header` flag:

```json
{
  "mcpServers": {
    "pine-mcp": {
      "command": "npx",
      "args": [
        "mcp-remote",
        "https://pine-mcp.netlify.app/mcp",
        "--header",
        "x-pine-mcp-client:<your-repo-or-app-name>"
      ]
    }
  }
}
```

Leave out the space after the colon in the `--header` value. Some applications, including Cursor and Claude Desktop on Windows, don't escape spaces in `args`, which breaks the header. Any other client that only starts local servers can use the same `mcp-remote` entry.

### Other Applications

ChatGPT and other apps that add MCP servers from a settings screen rather than a config file take the URL `https://pine-mcp.netlify.app/mcp`. If an app can't send custom headers, its calls are grouped under its user agent.

### Check the Connection

Ask your assistant: "List the Pine components." It should call `list_pine_components` and answer with real `pds-*` names. If it answers without calling a Pine MCP tool, check that the server shows as connected in your app's MCP settings, then start a new chat.

## Use with the Pine Agent Skill

The `pine` agent skill tells a coding agent when to use these tools: it resolves every component, token and icon through Pine MCP before writing, and validates the result before calling the work done. It needs Pine MCP connected. Install it into your agent with:

```bash
npx skills add https://pine-design-system.netlify.app
```

Or copy <pds-link href="https://github.com/Kajabi/pine/tree/main/skills/pine" external>skills/pine</pds-link> from the Pine repository into your agent's skills directory.

## Example Usage

Once connected, AI assistants can:

```
Ask: "Show me how to create a button with Pine components"
→ AI queries Pine MCP and gets current `pds-button` documentation

Ask: "Show me all of the properties that are available for the pds-input component?"
→ AI queries Pine MCP and gets current `pds-input` properties

Ask: "What color tokens are available in the Pine Design System?"
→ AI gets filtered list of color tokens with CSS examples

Ask: "Validate this Pine layout code"
→ AI checks code against Pine rules and suggests fixes
```

## Benefits

- **Accurate Information** - AI gets real Pine component data instead of guesses
- **Consistent Code** - Generated code follows Pine patterns automatically
- **Time Savings** - No need to manually lookup component documentation
- **Quality Assurance** - Built-in validation prevents common mistakes

Pine MCP serves a snapshot of Pine taken at its last deploy, so it can trail a new Pine release. The component and design-doc tools accept `forceRefresh: true` to read live docs from GitHub instead.

Pine MCP makes it easy for AI assistants to work intelligently with the Pine Design System, ensuring consistent, compliant code generation and reducing the need for manual documentation lookups.
