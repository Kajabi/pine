# Using Pine Form Components

## Overview

Pine form controls work inside a native `<form>`. `pds-input`, `pds-textarea`, `pds-select`, `pds-checkbox`, `pds-switch`, `pds-combobox`, `pds-multiselect` and `pds-datepicker` are form-associated custom elements, so the form submits their values the way it submits native controls. `pds-radio` renders a native radio input in the page, outside any shadow root, and `pds-radio-group` gives a set of radios one name and one label. A `pds-button` with `type="submit"` submits the form it's in.

Each component's docs cover its own props and events. This guide covers what they share.

## Example

One `pds-box` with `direction="column"` and `gap="md"` spaces the fields, so the controls need no wrapper boxes. The live example doesn't send anything when you submit it, and the copied code is the form alone, so add your own submit handler.

});

## Rules

**Do:**

- Give every control a `component-id`. It connects the visible label to the field. A `pds-input` without one has no accessible name.
- Give every control you want submitted a `name`, set as an HTML attribute. The form leaves out a control without one. `pds-input`, `pds-textarea`, `pds-select`, `pds-checkbox`, `pds-switch` and `pds-datepicker` submit under their `name` attribute only, so a `name` set only as a property, as React 19 does for custom elements, leaves them out too. The `@pine-ds/react` components set the attribute for you.
- Group related radios in a `pds-radio-group` with a `group-label` and a `name`. Screen readers read the `group-label` as the group's name, every radio in it gets the `name`, and the group shows one `error-message` for all of them.
- Use `readonly` for a value people should see but not change, when the form should still send it. A `disabled` control isn't submitted. `pds-input`, `pds-textarea` and `pds-datepicker` have `readonly`.
- Write boolean props as bare attributes, such as `disabled`, and remove the attribute to turn one off. On form-associated controls such as `pds-input`, any value turns it on, even `disabled="false"`. In React, pass `disabled`, or `disabled={isDisabled || undefined}`: React 18 writes `disabled={false}` on a custom element as `disabled="false"`, which disables the control and leaves it out of the form.

**Don't:**

- Use `placeholder` as the label. It disappears once someone types.
- Log submitted values in production. Forms often hold personal details.

## Validation

Set `invalid` and `error-message` together when a field fails. `pds-select`, `pds-combobox` and `pds-multiselect` treat an `error-message` alone as invalid. On `pds-input`, `pds-checkbox`, `pds-switch`, `pds-radio` and `pds-datepicker`, an `error-message` alone shows the message but doesn't mark the field invalid for screen readers or connect the message to it. `pds-textarea` shows no `error-message` until `invalid` is set.

While a field is invalid, screen readers read its `error-message` as the field's description instead of its `helper-message`. Both messages stay on screen, except on `pds-combobox` and `pds-multiselect`, which hide the `helper-message` while an `error-message` is set.

With `required`, `pds-input` shows an asterisk after its label, and the browser won't submit the form while the field is empty.

### After a failed submit

When a submit fails, mark each field that failed with `invalid` and `error-message`. Above the form, show a `pds-alert` with `variant="danger"` that lists the errors, and move focus to it so keyboard and screen reader users start there. Give the alert `tabindex="-1"` so it can take focus, then call `focus()` on it. Give the alert an `id` so your script can find it. `component-id` doesn't set the alert's `id`.

Don't move focus while validating a single field as someone types or leaves it. Show its `error-message` and leave focus where it is.

### Waiting on the server

Set `loading` on the submit `pds-button` while a server check runs. A loading button sets `aria-busy="true"` on its own inner `<button>`, so don't add `aria-busy` to it. Put `aria-busy="true"` on a region only while your code replaces its content.

## Events

Each control reports changes with its own event, such as `pdsInput` on `pds-input` and `pdsCheckboxChange` on `pds-checkbox`. Setting `value` or `checked` from your code doesn't fire them. Each component's properties table lists its events, and the <pds-link href="../?path=/docs/guides-events--docs">Events</pds-link> guide covers how to listen to them, including in React.
